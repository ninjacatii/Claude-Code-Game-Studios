# Game Concept（游戏概念）：空当接龙：经典复刻

*Created: 2026-10-24*
*Status: Draft*

---

## Elevator Pitch（一句话概念）

> Windows 经典《空当接龙》的忠实复刻：同一套规则、同一张牌桌、同一种手感，用 Godot 在今天的 Windows 上重开一局。
>
> 10 秒测试：没玩过的人也能立刻理解——拖牌、整理、把整副牌按花色归位。

## Core Fantasy（核心幻想）

回到熟悉的旧牌桌前：规则、布局与操作都没有变。玩家不需要学习任何新东西，只需专注于把混乱整理成秩序。

这不是怀旧装饰，而是一种确定感——每一步都符合记忆中的规则，每一次落位都得到预期的反馈。

---

## Unique Hook（独特钩子）

像 1995 年的 Windows 空当接龙，而且什么都不加。

不做现代化、不做额外系统，只把原版体验准确地带到今天的 Windows 上。在“复刻”普遍被理解为“重做并加料”的当下，克制本身就是差异点。

---

## Reference Version（参考版本）

**参考基线：混合参考（Hybrid Reference）**

- **视觉与桌面手感**：Windows 95 FreeCell（1995）——绿桌、白色卡面、红/黑花色、经典灰色菜单；任何视觉元素必须能在 1995 版找到出处。
- **功能行为**：Windows 7 / Windows XP 经典 FreeCell——1–1,000,000 局号、提示、统计（局数/胜率/连胜）、撤销、F10 提示。
- **有意偏离清单**（逐条记录，不在实现中“顺手现代化”）：
  1. 局号范围 1–1,000,000；1995 原版为 1–32,000。
  2. 提示（Hint）与 F10 快捷键按 Windows 7/XP 行为；若 1995 版没有，视为功能扩展。
  3. 统计对话框与会话内统计按 Windows 7/XP 行为；MVP 不落盘。
  4. 撤销深度上限 4096 是工程约束，不声称是原版行为。
  5. 视觉保持 1995 风格，不采用 Windows 7 的现代主题。
  6. MVP 不做动画/音效打磨、教程、成就、联网、排行榜、云存档；这些是反支柱，不是偏离。
- **保真验证**：以 Windows 95 视觉截图 + Windows 7/XP 功能截图作为参考；无法获得的条目标 `NOT ASSESSED`，不得声称“与原版一致”。

## Player Experience Analysis（MDA 框架）

### Target Aesthetics（目标美学）

| 美学 | 优先级 | 如何实现 |
| ---- | ---- | ---- |
| **Sensation（感官）** | 3 | 卡牌落位与发牌的即时反馈；克制的原版风格界面 |
| **Fantasy（幻想）** | N/A | 无角色扮演 |
| **Narrative（叙事）** | N/A | 无剧情 |
| **Challenge（挑战）** | 1 | 牌局本身提供推理难度；难度由所选的局号决定 |
| **Fellowship（社交）** | N/A | 单人体验 |
| **Discovery（发现）** | N/A | 无隐藏内容或探索 |
| **Expression（表达）** | N/A | 无自定义或创作工具 |
| **Submission（放松）** | 2 | 重复的整理动作与安静界面带来低压力心流 |

### Key Dynamics（关键动态）

- 玩家会先扫视整张牌桌，再规划若干步之后的腾挪，而不是见牌就移。
- 玩家会优先腾出 A，并在自由单元紧张时重新评估整局。
- 玩家会记住并重试同一个局号，把“解不开”当成待解决的问题而非失败。

### Core Mechanics（核心机制）

1. 52 张牌的经典桌面规则：8 列牌堆、4 个自由单元、4 个回收单元。
2. 拖拽与双击移动；合法落位判定；双击自动送往回收单元。
3. 原版辅助：撤销、提示、重开本局、选局号。
4. 局号驱动的确定性发牌，以及局数、胜率、连胜的最小统计。

## Player Motivation Profile（玩家动机画像）

### Primary Psychological Needs Served（主要心理需求）

| 需求 | 如何满足 | 强度 |
| ---- | ---- | ---- |
| **Autonomy（自主）** | 选局号、撤销、重开与节奏完全由玩家掌握，无计时压力 | Core |
| **Competence（胜任）** | 读牌与规划能力随局数提升，胜率与连胜可见 | Core |
| **Relatedness（关联）** | 单人体验；局号提供弱共享参照（“你试过第 11982 局吗”） | Minimal |

### Player Type Appeal（玩家类型，Bartle 分类）

- [x] **Achievers（成就型）** —— 完成牌局、提升胜率与连胜。
- [x] **Explorers（探索型）** —— 研究牌局结构，寻找不同解法。
- [ ] **Socializers（社交型）** —— 不服务。
- [ ] **Killers/Competitors（竞争型）** —— 不服务。

### Flow State Design（心流设计）

- **上手曲线**：没有教程。界面自解释，首次进入直接发牌，操作与原版一致。
- **难度缩放**：难度由局号决定；玩家可以随时重开本局或换一个局号。
- **反馈清晰度**：每一步合法或非法都即时可见；统计记录胜率与连胜。
- **失败恢复**：一步重开本局，无惩罚、无结算界面。

## Core Loop（核心循环）

### Moment-to-Moment（30 秒）

拖起一张牌或一段合法序列，放到列、自由单元或回收单元；落位吸附；双击则自动送往回收单元。

每一步都可见地减少混乱，规则完全透明，没有隐藏状态，反馈即时。

### Short-Term（5–15 分钟）

一副牌局：扫视牌面 → 找阻塞点 → 规划腾挪顺序 → 解开关键牌。经典版一局通常几分钟。

### Session-Level（30–120 分钟）

连续多局。自然停点是一局结束（赢下或卡死）；回访理由是“同一局再来一次”或“试试下一个局号”。

### Long-Term Progression（长期进程）

刻意没有跨局成长。成长发生在玩家身上——读牌更快、更快识别模式；唯一记录是原版的局数、胜率与连胜统计。

### Retention Hooks（回访钩子）

- **Curiosity（好奇）**：刻意不提供。
- **Investment（投入）**：统计与连胜记录。
- **Social（社交）**：局号形成的弱共享参照。
- **Mastery（精通）**：胜率与解局速度的提升。

## Game Pillars（游戏支柱）

### Pillar 1: 原版规则，零改动

规则、局号生成与辅助功能与 Windows 经典版一致，不做“现代化改良”。

*Design test*：在“加入无限撤销或增强提示”与“保持原版”之间，选择保持原版。

### Pillar 2: 手感优先于画面

拖拽、落位、双击必须即时且可预期；视觉只服务于可读性。

*Design test*：在“更华丽的动画”与“更低的输入延迟”之间，选择更低延迟。

### Pillar 3: 一秒读懂牌面

任何时刻，玩家都能在 1 秒内看清可移动的牌、空位与可归位的牌；配色与层级遵循原版。

*Design test*：在“主题皮肤”与“原版对比度”之间，选择原版对比度。

### Pillar 4: 失败可无损重来

输局不是惩罚；重开本局或换局号必须在一两步内完成。

*Design test*：在“失败结算界面”与“直接重开本局”之间，选择直接重开。

### Anti-Pillars（反支柱）

- **不做剧情/战役模式**：原版没有；添加会稀释经典体验并扩大范围。
- **不做每日任务、成就、皮肤系统**：超出“经典复刻”，几周内无法保证质量。
- **不做联网、排行榜、云存档**：单人经典体验，联网会引入账号与服务器成本。
- **不做移动端触控优先**：目标只有 Windows 桌面，触控适配会改变交互与布局。

## Risks and Open Questions（风险与开放问题）

### Design Risks（设计风险）

- 纯复刻没有差异化；拖拽、双击、撤销等手感细节一旦不达标，会被直接拿去和原作比较。
- 原版的“提示”需要足够好用，否则玩家会认为不如原作。

### Technical Risks（技术风险）

- 局号洗牌与混合参考（Windows 7/XP 1–1,000,000）一致需要验证：Microsoft FreeCell 的发牌算法有公开实现，但需要移植并逐局校验。
- 拖拽手感、落位判定与窗口缩放在 Godot 中的实际表现需要尽早验证。

### Market Risks（市场风险）

- 经典复刻受众小，适合作为个人项目或免费发布，不追求商业成功。

### Scope Risks（范围风险）

- “原版手感”与“原版辅助”会诱发无止境的细节打磨；几周内必须锁定 MVP。

### Open Questions（开放问题）

- 局号洗牌是否必须与混合参考（Windows 7/XP 功能基线）完全一致？——在首个可运行版本中验证；若不可行，使用自有的确定性算法，并在文档中注明差异。
- 统计是否需要持久化到磁盘？——MVP 先保留会话内统计，持久化留到 Vertical Slice。

## MVP Definition（MVP 定义）

**Core hypothesis（核心假设）**：玩家在今天的 Windows 上拖拽、整理、完成牌局时，会感到“这就是经典空当接龙”。

**Required for MVP（MVP 必需）**：

1. 完整的空当接龙规则与合法移动判定。
2. 拖拽、双击、列/自由单元/回收单元的落位。
3. 新局、重开本局、撤销、提示、选局号。
4. 胜利/卡死判定与会话内最小统计。
5. Windows 窗口下的可读布局与缩放。

**Explicitly NOT in MVP（明确不做）**：

- 动画与音效打磨（先保证手感与规则）。
- 统计的磁盘持久化与长期战绩。
- 主题、皮肤与扩展设置项。

### Scope Tiers（范围分层）

| 层级 | 内容 | 功能 | 周期 |
| ---- | ---- | ---- | ---- |
| **MVP** | 核心牌桌与 52 张牌 | 规则 + 原版辅助 | 2 周 |
| **Vertical Slice** | 完整视觉与音效 | 核心 + 统计持久化 | 3 周 |
| **Alpha** | 全部功能，细节待打磨 | 完整辅助 + 设置 | 4 周 |
| **Full Vision** | 与原版手感对齐的完成版 | 全部功能 + 打磨 | 5 周 |

## Visual Identity Anchor（视觉身份锚点）

**方向名称**：经典复刻（Classic Replica）

**一句话视觉规则**：任何视觉元素都必须能在 1995 年的 Windows 空当接龙里找到出处；找不到就不加。

**支撑原则**：

1. **原版配色为准**：绿色桌面、白色卡面、红/黑花色、蓝色高亮。
   *Design test*：新配色与可读性冲突时，选择原版。
2. **卡面信息优先**：点数与花色在任何缩放下都必须清晰。
   *Design test*：装饰与字号冲突时，先减小装饰。
3. **动效克制**：只保留发牌与落位吸附两类动效，单次短于 150ms。
   *Design test*：新动效无法说明玩家收益时，删除。

**色彩哲学**：低饱和绿色桌面作为安静背景；卡牌白底配黑/红字提供最高对比；唯一的高亮色只用于**提示**指出的落点，不用于装饰或拖拽合法落点。
